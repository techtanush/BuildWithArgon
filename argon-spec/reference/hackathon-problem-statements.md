# Hackathon Problem Statements (as published by the organizers)

## Your Goal: Hackathon Problem Statements

You'll build in at least one of the hackathon's problem statements.

### Problem Statement One: Million Token Engineering

Gemini 4 Argon is SOTA on [codebase understanding](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/#workingharder),
which measures long-horizon software engineering. With up to 1M continuous output tokens in a
single response, Argon makes it possible to build systems that work across hundreds of files, keep
interfaces consistent as they change, and grind tedious tasks where other models' accuracy drops
off. The work teams put off for years (legacy migrations, language translations, framework
upgrades) is exactly where that scale matters. Pick something that has before seemed as a
monumental task, do it, and measure your improvement over a baseline.

### Problem Statement Two: More Dimensions

Gemini 4 Argon is also SOTA on [long video understanding](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/#workingharder),
and its output window lets it generate high-fidelity [3D games and procedural worlds](https://aistudio.google.com/learn/building-3d-games-and-worlds-with-gemini-4-argon)
in a single pass. A single pass is only the first draft. Build a system that renders what it made,
watches the result, critiques it against the goal, and fixes it in a loop.
