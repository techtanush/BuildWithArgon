# Safe starter demo handoff

Implemented opt-in API, not an autonomous full-company start:
- `POST /v1/ventures/{vid}/starter/start` JSON `{"budget_usd":0.25}`
- `GET /v1/ventures/{vid}/starter`
- `GET /v1/ventures/{vid}/starter/preview`

All routes use the existing bearer/gateway ownership policy. POST is idempotent per venture and requires live Gemini credentials. The start action persists explicit authorization before any model attempt and creates exactly four dependent scheduler tickets: `starter.plan`, `starter.build`, `starter.qa`, `starter.review`. A draft venture becomes running; no intake or normal department DAG is created.

The plan makes one typed-content call, no JSON repair or kernel provider retry. Existing Flash `agent_request` is preferred when verified prices exist. Otherwise isolated `starter_content` uses known-priced Argon medium, maximum 4096 output tokens, 120-second provider timeout. With repository Argon rates ($2 input/$10 output per million), conservative 24000 input-token allowance plus output limit bounds the request estimate at $0.08896. Requested cap is at most $0.25 and must fit remaining venture budget. Pricing changes and provider invoices remain external; actual usage is recorded through the normal ledger. A durable attempt marker prevents automatic restart/retry from spending again. Founder ideas over 12000 UTF-8 bytes are rejected rather than silently truncated.

The remaining stages execute only trusted Python rendering and deterministic checks, never model code, shell commands, Docker, or browser control. Run records label these stages `none (deterministic)`. Source JSON/HTML, test report and preview artifacts are persisted by the existing scheduler. Completion emits engineering-channel evidence refs and the relative preview URL via normal SSE events. Strict CSP denies scripts, network, forms and external frames. Preview integrity is checked against the persisted artifact hash before serving.

Scope: a genuine model-authored **static landing-page prototype**, not a backend application. No AI tutor, registration, account handling, payment flow or live product integration is included in the generated page. These omissions appear on the page and final message. No absolute localhost URL is claimed. Marketing remains a separate explicit action using its existing handler/PDF pipeline; starter never silently starts marketing spend.

Unit verification uses fake providers and temporary databases only. The full starter plan/build/QA/review scheduler path, actual ledger/run/artifact/message records, HTML escaping, tamper rejection, fake-mode refusal, cap checks, gateway tenant isolation and single-attempt behavior are covered in `tests/test_starter.py`. No live Gemini request, real venture start, provider write, app restart or active database mutation was performed by this worker.

## 17:25 tutor update supersedes the static-only limitation above
User explicitly approved a prebuilt scenario/template with adaptive Gemini responses. The trusted renderer now includes a fixed tutor widget (`departments/starter_widget.py`). Its sole script is CSP SHA-256 authorized, writes model output with `textContent`, and connects only to the same-origin owner-scoped `/v1/ventures/{vid}/starter/tutor` broker. Existing verified legacy preview artifacts receive this fixed widget at serving time; new source artifacts include it directly.

Broker (`api/starter_tutor.py`) accepts a question of at most 2000 characters and six history turns of at most 1000 characters each, with a separate total UTF-8 limit. It passes no company idea, files, private records, credentials or tools to the model. `starter_tutor` uses known-priced Argon low thinking with 1024 output tokens, a single provider attempt and actual ledger/run tracking. Each send checks the venture's remaining budget against a conservative estimated bound ($0.05024 at repository rates), capped at $0.06. A durable per-venture in-flight guard and ten-per-minute rate limit apply. The app has no student accounts or public end-user authentication; it is an owner-authenticated prototype. No live provider calls were made in implementation or QA.

## 17:30 secure-provider, real private authentication, fast scenario
- Explicit fast scenario: `POST /v1/ventures/{vid}/starter/start` with `{"scenario":"ai_tutor_demo","budget_usd":0.25}`. Uses prebuilt typed tutor copy and four actual deterministic scheduler stages. No content model call; every stage records `none (deterministic)`. Omitting scenario preserves the generic model-content workflow. This does not seed or remove the normal company DAG.
- Preview includes real private signup/login/logout, integrated from `api/starter_auth.py`. Tutor calls require a server-verified opaque HttpOnly session cookie. The gateway owner identity remains mandatory: `AUTH_MODE=gateway`, configured bearer secret, verified `x-ycbf-user-id`, venture owner mapping, and exact `WEB_URL` browser Origin. Local bearer-only mode deliberately refuses these accounts. This is not public student SaaS authentication.
- Owner-scoped GET `/starter/provider` returns only `{"configured":boolean}`. POST takes `{"api_key":"..."}` only via the secure password form, with JSON content-type, max4096-byte raw body, SecretStr parsing and sanitized no-echo errors. There is no key-validation provider call. Saving explicitly selects OpenAI for subsequent user-initiated tutor sends.
- Provider keys are AES-GCM encrypted in venture-scoped database records with venture/provider associated data. The separate generated master encryption key resides in runtime `data_dir/.secrets/starter-master.key` (0700 directory,0600 file), explicitly gitignored. Never publish or include this runtime key or data in artifacts. Back it up securely with runtime data; losing it makes stored credentials undecryptable. No reusable encrypted store existed in the inspected kernel.
- The OpenAI broker fixes its destination to `https://api.openai.com/v1/chat/completions`, disables redirects and environment proxies, uses `gpt-4o-mini` with max512 output tokens, no tools and no retries. Actual response model/usage/cost go to existing run and ledger records. Official standard rates verified 2026-10-25: input $0.15/M, output $0.60/M, source https://developers.openai.com/api/docs/models/gpt-4o-mini.md . Conservative per-turn OpenAI bound is $0.0033072, still subject to venture budget and existing tutor rate/in-flight limits. Gemini remains the default until OpenAI is explicitly selected; company-agent routing is unchanged.
- Fixed widget JavaScript passes `node --check`, uses hash-only CSP and textContent, clears password/key fields immediately, and never writes credentials into chat, browser storage, source files or provider logs. Existing verified preview artifacts are upgraded to the current fixed widget safely at serving time. Final engineering completion messages direct the owner to this secure form, never request keys in ordinary chat.
- Final combined verification: **147 tests passed** (starter, provider, auth, tutor, gateway, LLM client, scheduler), using fake providers and temporary databases. No live model request, paid validation request, active database mutation, restart or GitHub push occurred in this implementation session. Manual backend restart is required.
